# open-rally 설계 문서

작성일: 2026-11-06

## 의도

여러 대의 PC를 관리하는 한 사람이, PC 사이에서 값과 파일을 주고받기 위한 **로그인 없는 공용 게시판**이다.
구체적인 장면은 `.env` 내용, API 키, 작은 실행 파일, 스크린샷, 영상을 한 PC에서 올려두고 다른 PC에서 브라우저로 열어 복사하거나 내려받는 것이다.

Slack이나 메신저는 매 PC마다 로그인해야 해서 쓰지 않는다. 같은 LAN 또는 Tailscale 안에 있는 PC가 브라우저만 열면 바로 보이는 것이 핵심이다.

서버는 사용자의 개인 Mac에서 돌며, 메뉴바(트레이) 아이콘으로 켜고 끈다. 꺼져 있을 때는 리소스를 거의 쓰지 않아야 한다.

## 목표

- 같은 네트워크(LAN / Tailscale)의 어떤 PC든 브라우저로 `http://<ip>:<port>` 에 접속하면 같은 게시판을 본다. 계정은 없고, 사용자만 아는 **비밀번호 하나**를 PC 마다 처음 한 번만 입력한다 (사용자 요청).
- 텍스트, 이미지, 영상, 그 밖의 아무 파일이나 올릴 수 있다.
- 텍스트는 버튼 한 번으로 전체 복사된다. 파일은 버튼 한 번으로 내려받는다.
- 한 PC에서 올리면 열려 있는 다른 PC의 화면에 새로고침 없이 나타난다.
- 글은 영구 보관한다. 삭제는 사용자가 글마다 직접 한다.
- Mac 메뉴바 아이콘 메뉴에서 서버를 켜고 끈다. 꺼진 동안은 포트가 닫히고 메뉴바 프로세스만 남는다.
- 실행 파일 하나로 동작한다. 접속하는 PC에는 아무것도 설치하지 않는다.

## 비목표 (이번에 하지 않음)

- 사용자 계정, 권한 구분 (비밀번호 하나로 전부 열린다)
- 방/채널 분리, 작성자 표시 (모두 한 사람이 쓰므로 시간순 단일 목록이면 충분)
- 글 수정, 검색, 자동 만료
- 메시지 암호화, HTTPS
- Windows / Linux 메뉴바 지원 (서버 코드는 크로스플랫폼이어도 되지만 트레이는 macOS만 검증한다)
- 모바일 앱

## 안티 목표 (이렇게 되면 실패)

- 인터넷이나 남의 네트워크에 노출되는 것. 서버 Mac은 외부 Wi-Fi 에도 붙는 노트북이므로(사용자 확인), 기본은 Tailscale 인터페이스에만 열고 LAN 공개는 사용자가 그때그때 켜는 것으로 한다. 설계에서 외부 공개를 돕는 기능(터널, 공개 URL)을 넣지 않는다.
- 서버를 껐는데도 CPU나 메모리를 계속 쓰는 것.
- 접속하는 PC 쪽에 설치나 설정이 필요해지는 것.
- 큰 영상을 올릴 때 서버가 파일 전체를 메모리에 올리는 것.

## 제약

- 언어는 **Rust**. (사용자 선택)
- 서버 머신은 macOS (Darwin 27). Rust 툴체인은 이미 설치돼 있다 (cargo 1.99).
- Tailscale이 설치돼 있고 이 Mac의 Tailscale IPv4는 `100.100.100.100` 으로 표기한다 (실제 값은 사용자 환경에 따라 다름).
- 접속 클라이언트는 최신 데스크톱 브라우저(Chrome, Safari, Edge)로 가정한다.

## 구조 (사용자가 정한 것과 내가 정한 것)

### 프로세스 구성 — 내 선택

단일 바이너리 `open-rally` 가 메뉴바 앱으로 실행된다. 같은 프로세스 안에서 HTTP 서버를 켜고 끈다.

- 메뉴바: `tao` 이벤트 루프 + `tray-icon` + `muda` 메뉴.
- 서버: `tokio` 런타임 위의 `axum`. "켜기"는 리스너를 열고 서버 태스크를 spawn, "끄기"는 graceful shutdown 신호를 보내고 태스크 종료를 기다린 뒤 리스너를 닫는다. 꺼진 상태에서는 tokio 런타임은 살아 있어도 실행 중인 태스크가 없다.
- 저장: `rusqlite` (bundled SQLite). 업로드 파일은 디스크에 그대로 둔다.
- 프론트엔드: 빌드 단계 없는 단일 HTML + vanilla JS. `include_str!` 로 바이너리에 포함한다.
- macOS 에서 Dock 아이콘 없이 메뉴바에만 보이게 하려면 `.app` 번들과 `LSUIElement=true` 가 필요하다. `cargo build --release` 결과를 `.app` 으로 싸는 스크립트를 함께 둔다. 번들 없이 바이너리를 직접 실행해도 동작은 해야 한다 (Dock 아이콘이 뜨는 것만 감수).

### 메뉴바 메뉴 — 사용자가 "UI로 켜고 끄기"를 정했고, 항목 구성은 내 선택

```
● 서버 실행 중 · 포트 7777          (꺼져 있으면 "○ 서버 꺼짐")
   http://100.100.100.100:7777         (비활성 텍스트, 꺼져 있으면 숨김)
   http://192.168.0.12:7777          (LAN 공개가 켜져 있을 때만)
────────────────
서버 끄기 / 서버 켜기               (상태에 따라 라벨 토글)
브라우저에서 열기                   (켜져 있을 때만 활성)
접속 주소 복사                      (켜져 있을 때만 활성, Tailscale 주소)
────────────────
LAN 에도 공개                       (체크 항목, 기본 꺼짐)
비밀번호 파일 열기
데이터 폴더 열기
────────────────
open-rally 종료
```

- 아이콘은 켜짐/꺼짐 두 가지 상태를 구분할 수 있게 한다 (예: 채워진 원 / 빈 원 템플릿 이미지).
- **바인딩 (사용자가 "외부 Wi-Fi 도 쓴다"고 확인, 방식은 내 선택).** 기본은 Tailscale 인터페이스 IP(`100.64.0.0/10` 대역) 와 `127.0.0.1` 에만 리스너를 연다. 카페 Wi-Fi 에 붙어도 같은 망의 다른 기기에서는 포트가 보이지 않는다.
  - "LAN 에도 공개" 를 체크하면 `0.0.0.0` 에 다시 바인딩한다 (서버를 내렸다 올린다). 이 설정은 저장하지 않는다. 앱을 다시 켜면 항상 꺼진 상태로 시작한다.
  - Tailscale 인터페이스가 없으면(꺼져 있거나 미설치) `127.0.0.1` 에만 열고 상태 줄에 "Tailscale 없음 · localhost 만" 으로 보여준다. "서버 켜기" 를 다시 누르면 인터페이스를 다시 찾는다.
- "접속 주소" 는 Tailscale IP 를 보여준다. LAN 공개가 켜져 있으면 LAN IP 를 한 줄 더 보여준다.
- 앱 시작 시 서버를 자동으로 켤지 여부는 **켠다** 로 한다. 앱을 실행했다는 것 자체가 쓰겠다는 뜻이기 때문이다. 끄고 싶으면 메뉴에서 끈다.
- 로그인 시 자동 실행은 이번 범위에 넣지 않는다. 사용자가 직접 로그인 항목에 등록하면 된다.

### 게시판 화면 — 사용자가 채팅형을 선택

사용자는 목업 중 **채팅형(B)** 을 골랐다.

- 입력창이 화면 아래, 글 목록은 위에 시간순으로 쌓이며 최신 글이 맨 아래.
- 새 글이 도착하면 아래로 자동 스크롤한다 (사용자가 위로 스크롤해 읽는 중이면 자동 스크롤하지 않는다 — 내 선택).
- 상단 바에 앱 이름, 접속 중인 주소, 연결 상태 점(WebSocket 연결 여부).

입력창:

- 여러 줄 텍스트 입력. `Cmd+Enter` (Windows는 `Ctrl+Enter`) 로 전송. `Enter` 는 줄바꿈 (.env 같은 여러 줄 붙여넣기가 주 용도이므로 — 내 선택).
- 파일 첨부 버튼, 드래그 앤 드롭, 클립보드 이미지 붙여넣기(`Cmd+V`)를 모두 지원.
- 한 글에 텍스트와 파일 여러 개를 함께 올릴 수 있다. 텍스트만, 파일만도 가능. 둘 다 없으면 전송 불가.
- 업로드 중에는 진행률을 보여준다 (영상이 클 수 있으므로).

글 한 개의 표시:

- 작성 시각 (오늘이면 `14:02`, 아니면 `11/05 14:02`).
- 텍스트는 고정폭 글꼴, 공백과 줄바꿈 그대로, 마크다운 해석 없음. 오른쪽에 **복사** 버튼. 복사 후 1~2초 "복사됨" 표시.
- 이미지 첨부는 인라인 미리보기(최대 높이 제한). 클릭하면 원본을 새 탭에서 연다.
- 영상 첨부는 인라인 `<video controls>`. 서버는 Range 요청을 지원해야 한다.
- 그 밖의 파일은 아이콘 + 파일명 + 크기 + **다운로드** 버튼 카드로 보여준다.
- 각 글에 **삭제** 버튼. 한 번 확인(confirm) 후 삭제. 삭제하면 첨부 파일도 디스크에서 지운다.

페이징: 처음 열면 최근 100개를 불러오고, 맨 위로 스크롤하면 이전 100개를 더 불러온다 (내 선택).

### 데이터 — 내 선택

저장 위치: `~/Library/Application Support/open-rally/`

```
open-rally.db          SQLite
uploads/<post_id>/<원본 파일명>
```

스키마:

```sql
CREATE TABLE posts (
  id         TEXT PRIMARY KEY,   -- ULID (시간순 정렬 가능)
  created_at INTEGER NOT NULL,   -- unix ms
  body       TEXT                -- NULL 이면 파일만 있는 글
);
CREATE TABLE attachments (
  id        TEXT PRIMARY KEY,    -- ULID
  post_id   TEXT NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  filename  TEXT NOT NULL,       -- 원본 파일명 (경로 구분자 제거)
  size      INTEGER NOT NULL,
  mime      TEXT NOT NULL,       -- 업로드 시 브라우저가 준 값, 없으면 확장자로 추정
  kind      TEXT NOT NULL        -- 'image' | 'video' | 'file' (mime 으로 판정, 화면 표시용)
);
```

- 업로드는 multipart 스트리밍으로 받아 디스크에 바로 쓴다. 전체를 메모리에 올리지 않는다.
- 파일 크기 상한은 두지 않는다 (디스크가 상한).
- 파일명은 경로 탈출이 안 되도록 `/`, `\`, `..` 를 제거하고, 비면 `file` 로 둔다.

### HTTP API — 내 선택

```
GET    /                         게시판 HTML (쿠키가 없거나 틀리면 비밀번호 입력 화면)
POST   /api/login                {"password": "..."} → 맞으면 세션 쿠키 설정, 틀리면 401
GET    /api/posts?before=<id>&limit=100    글 목록 (최신순, before 가 있으면 그 이전)
POST   /api/posts                multipart: body(텍스트, 선택) + files[] (0개 이상)
DELETE /api/posts/:id            글과 첨부 삭제
GET    /files/:attachment_id/:filename     첨부 다운로드/스트리밍 (Range 지원, 이미지·영상은 inline, 그 외 attachment)
GET    /ws                       WebSocket. 서버→클라이언트 이벤트만: {"type":"created", post} / {"type":"deleted", id}
```

`/` 와 `/api/login` 을 뺀 모든 경로는 유효한 세션 쿠키가 있어야 한다. 없으면 API 는 `401`, `/files` 와 `/ws` 도 `401` 이다.

클라이언트는 WebSocket 이 끊기면 지수 백오프로 재접속하고, 재접속 시 마지막으로 본 글 이후를 다시 받아온다.

### 설정 — 내 선택

- 포트 기본값 `7777`. 환경변수 `OPEN_RALLY_PORT` 로 변경. 설정 파일은 만들지 않는다.
- 데이터 폴더도 `OPEN_RALLY_DATA_DIR` 로 바꿀 수 있다.
- 포트가 이미 사용 중이면 메뉴바 상태에 "포트 7777 사용 중" 으로 보여주고 서버는 꺼진 상태로 둔다.

### 보안 — 사용자가 "비밀번호 하나만 치는 수준"으로 정함

- **비밀번호 (사용자 요청, 방식은 내 선택).** 계정 없이 공용 비밀번호 하나다.
  - 비밀번호는 데이터 폴더의 `config.toml` 에 `password = "..."` 로 둔다. 파일이 없으면 첫 실행 때 무작위 12자로 만들어 쓰고, 메뉴의 "비밀번호 파일 열기" 로 사용자가 바꾼다. 바꾼 값은 서버를 다시 켤 때 읽는다.
  - 브라우저는 처음 열면 비밀번호 입력 화면을 본다. 맞으면 서버가 무작위 세션 토큰을 만들어 `HttpOnly; SameSite=Lax; Max-Age=30일` 쿠키로 준다. 토큰은 서버 메모리에 들고 있고, 서버를 끄면 사라진다 (다시 켜면 각 PC 가 한 번 더 입력한다 — 단순함을 위해 저장하지 않는다).
  - 비밀번호 비교는 상수 시간 비교를 쓴다. 틀린 시도가 5번 쌓이면 그 IP 는 10초 동안 거절한다. 그 이상의 잠금은 두지 않는다.
  - 비밀번호가 평문으로 디스크에 있는 것은 감수한다. 이 파일은 서버 Mac 의 사용자 홈 안에만 있다.
- 이 비밀번호는 "같은 망의 누군가가 우연히 보는 것" 을 막는 수준이다. HTTP 평문이므로 같은 망에서 패킷을 보는 사람은 막지 못한다. 그래서 기본 바인딩을 Tailscale 로 두는 것이 여전히 중요하다.
- 그래도 경로 탈출, 디렉토리 리스팅 같은 기본적인 것은 막는다.
- 바인딩은 위 "메뉴바 메뉴" 절의 규칙을 따른다. 기본은 Tailscale + localhost, LAN 은 메뉴에서 켤 때만.
- **브라우저 경유 공격 차단 (내 선택, 리뷰 반영).** 접속 PC는 인터넷도 쓰므로, 쿠키를 가진 브라우저에서 악성 웹페이지가 이 게시판에 글을 쓰거나(CSRF) DNS rebinding 으로 내용을 읽어가는 것을 막는다. 비밀번호가 있어도 쿠키가 자동으로 붙으므로 이 검사는 그대로 필요하다.
  - 모든 요청의 `Host` 헤더를 검사한다. 허용: `localhost`, `127.0.0.1`, `[::1]`, 사설 대역 IP(`10/8`, `172.16/12`, `192.168/16`), Tailscale 대역(`100.64/10`), `*.local`, `*.ts.net`. 그 외는 `421` 로 거절한다. 포트는 비교에서 뺀다.
  - 상태를 바꾸는 요청(`POST`, `DELETE`)과 `/ws` 업그레이드는 `Origin` 헤더가 있으면 그 host 가 위 허용 목록에 들어야 한다. `Origin` 이 없는 요청(curl 등)은 허용한다.
  - 첨부 파일 응답에는 `X-Content-Type-Options: nosniff` 를 붙이고, `image/svg+xml`, `text/html`, `application/xhtml+xml` 은 인라인이 아니라 항상 `Content-Disposition: attachment` 로 내려준다. 같은 origin 에서 스크립트가 실행되는 것을 막기 위해서다. 화면의 이미지 미리보기 대상도 svg 는 제외한다.
  - 게시판 HTML 에는 `Content-Security-Policy: default-src 'self'; img-src 'self' blob:; media-src 'self'; connect-src 'self' ws: wss:` 수준의 CSP 를 건다. 인라인 스크립트는 쓰지 않는다 (스크립트도 `/app.js` 로 분리해 바이너리에 포함).
- **복사 버튼 (내 선택, 리뷰 반영).** `http://` 는 보안 컨텍스트가 아니라 `navigator.clipboard` 를 쓸 수 없다. 사용자 클릭 안에서 `document.execCommand('copy')` 를 쓴다. 현재 데스크톱 Chrome/Safari/Edge 에서 모두 동작한다. 실패하면 해당 텍스트 블록을 전체 선택 상태로 만들고 "Cmd+C 로 복사하세요" 를 띄운다. HTTPS 는 여전히 비목표다.
- **영상 재생 (내 선택, 리뷰 반영).** 서버는 트랜스코딩하지 않는다. 브라우저가 코덱을 못 틀면(`<video>` 의 `error` 이벤트) 그 자리에 다운로드 카드를 대신 보여준다. 완료 기준 4 의 "인라인 재생"은 브라우저가 지원하는 포맷(H.264 mp4, webm) 기준이다.

## 빌더에게 맡기는 것

- 크레이트 버전 선택과 Cargo 구성.
- 메뉴바 아이콘 이미지 (단순한 템플릿 아이콘이면 충분).
- 프론트엔드의 세부 스타일. 목업의 분위기(흰 카드, 회색 배경, 고정폭 텍스트 블록)를 따르되 픽셀 단위로 맞출 필요는 없다.
- WebSocket 재접속 간격, 자동 스크롤 임계값 같은 수치.
- `.app` 번들 생성 방식 (스크립트 또는 `cargo-bundle`).
- 테스트 범위. 최소한 API(글 생성/목록/삭제, 파일 저장과 삭제, 파일명 정제)는 자동 테스트로 덮는다.

## 완료 기준

1. 이 Mac에서 `.app` 을 실행하면 메뉴바에 아이콘이 뜨고 서버가 켜진다.
2. 다른 PC에서 `http://100.100.100.100:7777` 을 열면 비밀번호 화면이 나오고, 맞는 비밀번호를 넣으면 게시판이 보인다. 탭을 닫았다 다시 열어도 다시 묻지 않는다. 틀린 비밀번호로는 글 목록과 파일에 접근할 수 없다.
3. 한 PC에서 텍스트를 올리면 다른 PC 화면에 새로고침 없이 나타나고, 복사 버튼으로 전체가 복사된다.
4. 100 MB 이상의 영상을 올려도 서버 메모리가 파일 크기만큼 늘지 않고, 다른 PC에서 인라인 재생된다.
5. 실행 파일을 올리고 다른 PC에서 내려받으면 바이트가 동일하다.
6. 메뉴에서 "서버 끄기"를 누르면 포트가 닫히고, 다시 켜면 이전 글이 그대로 있다.
7. 글을 삭제하면 목록과 디스크에서 모두 사라진다.
8. 기본 상태에서는 같은 Wi-Fi 의 다른 기기에서 `http://<LAN IP>:7777` 이 열리지 않고, "LAN 에도 공개" 를 켜면 열린다.
